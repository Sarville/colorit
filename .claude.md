# Colorit - project notes for Claude

## Deployment (manual, no CI)
- VK build: `NEXT_PUBLIC_REQUIRE_VK=true yarn next build && yarn next export`, then
  `rsync -az --delete out/ server-games:/opt/games/site/vk/colorit/` (`server-games` is an SSH
  alias).
- Server runs Caddy (`caddy-games` container, config at `/opt/games/Caddyfile` on the host) and a
  small Node service `vk-payments-colorit` (payments webhook + VK launch-auth gate, code at
  `/opt/games/vk-payments/server.js` on the host). **Neither of those two files is in this git
  repo** - they're server-only, edited in place over SSH, with ad hoc `.bak-*` copies as the only
  history. `vk-payments-colorit` needs `docker restart vk-payments-colorit` after any edit (no
  hot-reload); Caddy needs `docker exec caddy-games caddy reload --config /etc/caddy/Caddyfile`
  after validating with `caddy validate`.
- Before touching anything VK-related (payments, auth, storage, Caddy config), read
  [`docs/vk-gotchas.md`](./docs/vk-gotchas.md) - it documents several non-obvious traps that already
  cost real debugging time: `@vkontakte/vk-bridge`'s types being wrong for the order box response,
  VK's storage 4096-byte-per-key silent truncation, Caddy's `path` matcher not supporting `**`
  across segments in the deployed version, and how the VK launch-params auth gate works.

## Conventions
- Session summaries go in `sessions/YYYY-MM-DD-HHMM-session.md` (see existing ones for format).
- Always run `npx tsc --noEmit` after edits; there's no separate lint/test step configured.
- When editing the server-only Caddy/payments files: back up with a timestamped copy before
  overwriting, `caddy validate`/`node --check` before applying, and verify with curl against the
  live site afterward (see recent session logs for the exact check patterns used).
