- **Sound latency fix** (`lib/sound.ts`): user reported audible delay on click/win sounds when tested inside the VK webview, even with `HTMLAudioElement` preloading. Root cause: `new Audio(src).play()` re-spins the media pipeline on every call, and the previous click "pool" of pre-loaded `<audio>` elements didn't fully eliminate that. Rewrote to use the Web Audio API: both sounds (`click.wav`, `won.wav`) are fetched and decoded once into in-memory `AudioBuffer`s at module load, then played via `AudioBufferSourceNode` (fresh node per play, routed through a `GainNode` for volume) — no per-play decode cost, and overlapping plays no longer need round-robin pooling since Web Audio handles concurrency natively.
